# 2026-10 현행화 노트

v2.6.0(2026-05) 이후 약 4.5개월 동안 바뀐 Claude Code와 하네스 생태계를 조사해서 템플릿에 반영한 내용과 근거를 기록한다. 조사일 2026-10-01.

## 근거 수준
- **공식 문서 확인** (code.claude.com): 훅 입력 스키마(stdin JSON), 권한 규칙 문법, skills/subagents frontmatter, `.mcp.json`, settings 우선순위.
- **GitHub 페이지 fetch로 확인했으나 수치는 근사**: 각 하네스의 스타 수와 규모. 마지막 커밋 날짜는 대부분 확인하지 못했다.
- **제안(공식 확인 없음)**: Supabase 마이그레이션·RLS 안전장치 훅의 구체 설계. 이 템플릿이 임시 저장소에서 동작을 테스트했을 뿐 공식 권장은 아니다.

## 템플릿에서 낡았던 것과 조치

| 항목 | 상태 | 조치 (v2.7.0) |
|---|---|---|
| 권한 `Bash(cmd:*)` | 현재 미지원, `Bash(cmd *)`만 유효 → 프리셋 규칙이 적용되지 않았을 가능성 | 3개 프리셋 교체 |
| 훅 `$CLAUDE_FILE_PATH` | 공식 문서에 없음. 입력은 stdin JSON | stdin JSON 파싱 |
| `PreCommit` 훅 | Claude Code 이벤트가 아님 (git hook) | 설명 정정 |
| 권한을 `settings.local.json`에 설치 | 개인용/gitignore 대상이라 팀 공유 불가 | 기본 `settings.json` (`--settings-file local`로 이전 동작) |
| 커맨드를 `.claude/commands/`로 설치 | 동작은 하지만 skills가 표준 | `--commands-as skills` 옵션 (기본은 v3에서 전환 예정) |
| 구조·레이어 규칙이 `src/` 전제 | `src/` 없는 Next.js 프로젝트에서 규칙이 비어 있음 | 미해결 (알려진 한계, 프로젝트별 `boundaries.yaml` 조정 필요) |

## 생태계에서 가져온 아이디어 (조사 시점 기준, 수치 근사)

| 하네스 | 규모 | 가져온 것 / 안 가져온 것 |
|---|---|---|
| obra/superpowers | 스타 수십만 대 | TDD, 검증 후 완료 선언 → 이미 `tdd-strict`/`verify`와 겹침. 전체 설치는 컨텍스트 비용이 커서 채택하지 않음 |
| everything-claude-code | 스타 수십만 대, 에이전트·스킬 수백 개 | 선택 설치 철학. 규모는 채택하지 않음 |
| github/spec-kit, OpenSpec | 스타 수만~십만 대 | 변경 단위 spec 아이디어. Ouroboros의 seed/spec과 같은 계열이라 별도 도입 없음 |
| BMAD, SuperClaude | 스타 수만 대 | 역할극·커맨드 수가 많아 참고만 |

공통 경향은 "작게 시작하고 필요한 것만 고른다"이다. 이 템플릿의 에이전트 페르소나 11종·방법론 16종은 소규모 프로젝트에는 컨텍스트 비용이 크므로, 프로젝트 성격에 따라 `--methodology none` 또는 일부만 설치하는 것을 권장한다.

## 공식 베스트 프랙티스 요약 (설계 지침으로 반영)
- CLAUDE.md는 짧게. "이 줄을 지우면 Claude가 실수하는가?"가 기준이고, 가끔만 필요한 지식은 skill로 옮긴다.
- "예외 없이 매번" 해야 하는 일은 지시문이 아니라 훅으로 강제한다.
- 작성자와 리뷰어는 서로 다른 컨텍스트에서 돌린다 (`rls-security-reviewer`, 기존 `check-security-ai`의 격리 아이디어와 같은 방향).
- 검증은 증거(테스트 출력, 스크린샷)를 요구한다 (`verify` skill).

## Next.js + Supabase 특화
- Next.js 16.3은 `next dev`가 `AGENTS.md`/`CLAUDE.md`에 관리 블록(`BEGIN:nextjs-agent-rules`)을 자동으로 쓰고 갱신한다. 프로젝트 규칙은 이 블록 바깥에 쓴다.
- `next-devtools-mcp`를 `.mcp.json`에 추가하는 구성이 공식 블로그에서 안내된다.
- Supabase MCP 권고: 로컬 또는 읽기 전용, 프로젝트 한정, 운영 연결 금지, 수동 승인 유지, prompt injection 주의. 템플릿의 `.mcp.json`은 **로컬** 엔드포인트만 가리킨다.
- Supabase 공식 agent-skills(`supabase/agent-skills`)가 별도로 존재한다. 이 템플릿의 `supabase-migration` skill은 팀 규칙(불변 마이그레이션, 로컬 검증)에 집중한 보완재이고 대체재가 아니다.

## 검증
- `init.sh`를 임시 Next.js + Supabase 프로젝트에 3가지 옵션 조합(`--commands-as skills`, 기본값, `--settings-file local`)으로 실행해 산출물을 확인했다.
- `check-migrations.sh`: RLS 없는 새 테이블 차단, RLS 포함 통과, 기존 마이그레이션 수정 차단, 재작성 허용 플래그 통과.
- `pretool-guard.sh`, `post-edit-lint.sh`(stdin JSON)를 설치된 프로젝트에서 모의 입력으로 확인했다.
- 실제 Claude Code 세션에서의 훅 차단 동작은 별도 프로젝트에서 확인했다.
