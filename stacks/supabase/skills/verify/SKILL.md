# 로컬 검증 (증거 기반)

완료를 선언하기 전에 증거(명령 출력, 스크린샷)를 확보한다. 타입체크나 lint 통과만으로는 동작 검증이 아니다.

1. 정적 검사: 변경 파일에 대한 lint와 타입체크 (프로젝트의 `CLAUDE.md` 명령 참고). 기존 오류(baseline)와 이번 변경의 오류를 구분한다.
2. 환경: 로컬 DB/서비스가 떠 있는지 확인하고, 앱이 **로컬** 환경변수를 가리키는지 확인한다. 원격 운영 값으로 앱을 띄우지 않는다.
3. 서버를 백그라운드로 실행하고 준비될 때까지 기다린다.
4. 브라우저(claude-in-chrome 등)로 접속해 시드 계정으로 로그인하고, 변경한 기능의 인수 조건을 하나씩 확인한다.
5. 역할이 여러 개 관련되면 각 역할로 확인하고, 권한이 없는 역할의 접근이 차단되는지도 본다.
6. 브라우저 콘솔과 서버 로그에 새 오류가 없는지 확인한다.
7. 서버 프로세스와 열었던 탭을 정리한다.
8. 결과를 짧게 보고한다. 확인하지 못한 것은 확인하지 못했다고 적는다.
